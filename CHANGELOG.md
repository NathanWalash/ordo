# Changelog

All notable changes to Ordo are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- The message list kept loading past the first few hundred messages only when you scrolled again: a page that finished loading with the list already at the bottom stopped it there. It now carries on until everything in the folder is shown.
- Headless Ordo on Windows no longer crashes now and then as it exits (exit code 3221225477, an access violation) after a quick command such as `boards list`. The output was always complete, but scripts saw a failure. Ordo now waits for Electron to finish starting up before it exits.
- Running the tests no longer takes over your screen. On macOS the end-to-end tests run Ordo as a hidden background app: its window is never shown, it gets no Dock icon and it never becomes the active app. On Windows and Linux the window opens without taking focus. `ORDO_E2E_SHOW=1` shows the windows when you want to watch. Headless runs (`--headless`, the CLI and the MCP server) also start as background apps on macOS, so an agent using Ordo never steals focus either.
- Connecting iCloud now says what actually went wrong. A timeout, a secure-connection failure (public Wi-Fi sign-in pages, VPNs or antivirus that inspect traffic), no network and a dropped connection each get their own message and next step, instead of "Something went wrong talking to iCloud", which read as iCloud being down. iCloud refusing or limiting connections says so, with iCloud's own words, rather than calling your password wrong. A refused password says to use an app-specific password (an Apple ID password won't work), to check iCloud Mail is on, and, if your Apple ID isn't an iCloud address, to sign in with your @icloud.com address. iCloud Calendar being busy (HTTP 429 or 5xx) is reported as that too. The connect sheet's result is announced by screen readers.
- The MCP server works on Windows. Electron replaces standard input with an empty stream there, so the server closed as soon as a client connected; Ordo now reads it directly. If a client hangs up while a call is running (a clean-up, say), the call finishes and is saved, so it can still be undone; Ordo waits up to five minutes for it, even if the client cancelled it.
- Headless `calendar events` showed all-day events a day early for anyone east of UTC (and in the UK in summer), and times in UTC. **Changed output:** `calendar events --json` and the `ordo_calendar_events` MCP tool now give an all-day event's `start` and `end` as dates (`YYYY-MM-DD`, end exclusive) instead of timestamps; timed events are unchanged. The text output shows your local time. See [docs/headless.md](docs/headless.md#output).
- Headless: `undo 1e3` was read as clean-up 1000 and `--limit 0x10` as 16; numbers must be plain digits. Help for an unknown command is an error. `--` ends the options. Right-to-left marks and Unicode line separators from emails are removed from terminal output. An empty `--category` says so instead of asking for a scan.
- Bank statements saved as UTF-16 (Excel's "Unicode text") or in the Windows code page (Excel's "CSV" on Windows, where £ is one byte) import correctly instead of failing or skipping every row; a UTF-8 file with one stray Windows byte keeps its accents and € signs. A file Ordo can't open says so instead of failing inside Ordo.
- A quote inside a description (`ARGOS 32" TV`) no longer swallows the rows after it, decimal commas (`-3,41`) are no longer read as £341, and semicolon statements with commas in quoted descriptions are split correctly.
- A bill paid on the 31st stays due on the last day of the month instead of moving to the 28th after February. A bill whose payment day changed is due on its new day.
- Money pages and the Calendar stay quick with large statements: finding bills and pairing transfers no longer slow down with the square of the number of transactions.
- Calendars added by link or file: big files parse in a fraction of the time (15,000 events went from 10 seconds to 0.15), one broken event no longer hides the whole calendar, a file with a byte order mark is accepted, `RDATE` periods and events with `RDATE` and no `RRULE` are read correctly, an `EXDATE` in UTC excludes an occurrence in a named time zone, a recurring overnight event keeps its end time across a clock change, and `UNTIL` as a date includes that day. A link that redirects somewhere unreadable or stops downloading part way says so plainly, and a calendar that fails to add is never left half added. A broken or hostile calendar can't exhaust memory or keep Ordo busy for long: rules stop after a fixed amount of work for the whole calendar, and only so many events are read from a file that doesn't parse as a whole.
- The week view puts events at their clock time on the days the clocks change, and the agenda shows "All day" for the middle days of a multi-day event instead of "Until".

### Added

- Unclutter: an **Unsubscribe** button for each sender you can unsubscribe from (never people), with how it unsubscribes (one-click, web page or email) as its icon and tooltip. It opens the review sheet for just that sender, with Move to Trash off, so its emails stay in your inbox; the plain-http tick, the unsubscribe email preview and the different-domain warning still apply. Afterwards the row says **Unsubscribed** (or **Page opened** for a link to finish in your browser), worked out from clean-up history so it's still there after a restart. A failed unsubscribe says why and keeps the button. **Review and clear** works as before.
- Assistant: it's a general assistant too. It answers general questions, helps with writing and planning and does sums from the model's own knowledge, without looking anything up, and says when an answer is general knowledge rather than from your data. Anything about your mail, calendar, money, boards or Ordo still comes only from Ordo's tools, and every safety rule is unchanged. A general question sends only your question and the conversation so far. Each page's suggestions now mix the two, such as "What’s on this week?", "Help me plan my week" and "Draft a polite note to my landlord" on Home. See [docs/assistant.md](docs/assistant.md#general-questions-and-your-data).
- Assistant: act on email. It can move messages to Archive, Bin, Junk, the Inbox or one of your folders, flag or unflag them, mark them read or unread (at most 20 at a time, only messages Ordo has downloaded), undo the last move, and save a new message, reply, reply-all or forward to Drafts. Each change waits for a card listing every message by sender address, subject and date, with where it is now and where it goes. Folders are checked against iCloud's list. See [docs/assistant.md](docs/assistant.md#email).
- Assistant: send email you confirm. It can send a new email, a reply (threaded, and the original marked as answered) or a forward, at most one per question. The card is titled with the subject and the first recipient and shows From, every recipient's full address on its own line (no Bcc), the subject, what the assistant wrote in full, and the quoted or forwarded original in its own scroll box, with any attachments; it says it can't be unsent. Send works only after a 1.5 s pause (checked in the main process too) and after a real click or key press. "You asked for this" needs your words to ask, every address typed by you in full, and nothing else read but the email being answered; a reply only to the address the email you named came from gets an amber note instead; anything else, including a Reply-To pointing elsewhere or an address from email text, gets a red **Check this first** naming each address you didn't type. Hidden text can't ride along: invisible characters are removed and long gaps closed up, and the card always shows every character that's sent. Recipients go to the mail client one address per entry and are checked against the card just before sending, so a sender address with a comma inside quotes can't turn one listed recipient into two. Forwarded attachments show their full names and are refused if a name hides or reverses characters. A sent email is remembered for the conversation and never sent twice. Sending is the assistant's alone: never MCP or headless mode.
- Headless: `mail move`, `mail flag`, `mail mark` and `mail undo`, with `--allow-changes` and `--confirm`, and the MCP change tools `ordo_mail_move`, `ordo_mail_flag`, `ordo_mail_mark`, `ordo_mail_undo` and `ordo_mail_draft` (each needs `confirm: true`). There's still no way to send from headless mode or MCP. See [docs/headless.md](docs/headless.md#changing-mail).
- The Mail page reloads in place after the assistant changes mail, keeping your folder, and its suggested prompts include "Archive this week’s newsletters" and "Draft a reply to the last email from …" (which you finish yourself). The assistant's cloud OK now says it can move, flag and draft email, and send email you confirm.
- **Ask Ordo** (Money, exploratory): a page where Ordo learns how your money works.
  - Ask a question in your own words. The model answers by calling Ordo's query functions in a strict JSON loop checked with zod; every amount, date and count in the answer is a placeholder Ordo fills in from its own sums, and amounts and counts are shown as separate figures with Ordo's own label ("Net cost of Italy · £418.99"), and an answer with any digit, currency sign or amount in words of the model's own is refused, so the model never does the maths or passes a bank reference off as an amount. Tool results go back to it as data, never instructions. Anything it suggests remembering (never a note) is shown as Ordo's own sentence and only saved when you press Save; the same payback can't be saved twice.
  - Questions for you, with one-tap answers and no model needed: is a regular payment from someone money you pass on (Gabe's rent for Patrick), was money in a payback (exact, likely or to check), did it just pass through (a ticket resold and paid straight on), who is someone you pay back and forth with. Answers become facts; "No" and "Not now" stop a question coming back.
  - Loose ends: money you hold for someone that hasn't gone on yet (not counted as income), money people still owe you, and who you pay and who pays you.
  - Events and trips across every account with paid out, paid back and net, by type and by account; leave merchants out (Italy without Ryanair). Your share of a cost after paybacks (Ryanair £297.77, Amelie paid £148.80, yours £148.97).
  - This month so far against last month to the same day, all spending or one category (bank categories like Monzo's Home too), with caveats: HSBC and other banks show posting dates, and a statement that stops early isn't counted.
  - What Ordo knows: every fact in a plain sentence, with where it came from, and Forget. Set how each bank dates payments. Add a note in your own words.
  - Teach Ordo: a guided walk through your accounts, people, regular money in and paybacks.
  - Bills: a shared bill Ordo can work out from what you taught it (a flatmate's money you pass on) shows its split in Detected; confirming saves the bill and the split. The flatmate's held payments count as paying their share, so Bills doesn't say they still owe it.
- Settings → AI: Ask Ordo answers briefly or in detail, can ask you a short question back (on by default), and, with a cloud model, needs its own consent to send exact amounts, dates and names, separate from the existing cloud consent. Switching provider clears both. A local model needs neither. See [docs/ai.md](docs/ai.md#ask-ordo).
- `money-core`: a memory store in `money.sqlite` (facts and dismissed questions) and pure engines: ledger, payback and pass-through matching, event cost, held money and owed-to-you, month-to-date comparison, date caveats, questions, bill suggestions and the Ask tool loop.
- Headless: `money knows`, `money questions`, `money loose-ends`, `money events` and `money compare`, and the matching MCP tools; `money answer` and `money forget` (and `ordo_money_answer`, `ordo_money_forget`) need `--allow-changes` and a confirm.
- Unit tests can never reach the real network: a Vitest setup file blocks `net`, `tls` and `dns` for anything but loopback, and points the iCloud IMAP, SMTP and CalDAV settings at a closed local port by default. See CONTRIBUTING.md.
- Boards: local kanban boards in the sidebar, kept in their own database on this computer (`boards.sqlite`). Make boards from the Simple, Weekly plan or Project templates; add, rename, reorder and delete boards and columns; give a column a card limit (it turns red when over, nothing is blocked) or mark it as done. See [docs/boards.md](docs/boards.md).
- Cards have a title, notes in simple markdown (drawn without HTML, https links only), coloured labels, a due date or date range, a checklist and custom fields you define per board: text, number, date, choice, checkbox, link and person. Fields can show on the card.
- Drag cards between and within columns and drag columns by their header, with a lifted card and a gap where it will land; Escape cancels. Every move also works from the keyboard (⌥ and the arrow keys, arrows alone to move between cards, the card's menu) and is announced to VoiceOver. Order is kept with fractional ranks, so a move rewrites one card.
- Quick add at the bottom of each column, search (⌘F) across titles, notes, labels and fields, and filters by label, date and field. Archive cards and restore them; deletes show Undo (and ⌘Z).
- Link a card to a calendar event, an email, a bill or payment in Money, or another card. Links are looked up again when the card opens and say when something can't be found any more; linked cards show it from both sides.
- Cards with a due date or range show on the Calendar as Boards, with Open in Boards. **Create card from this…** on a calendar event makes a card linked to it.
- Suggest on a card: the model chosen in Settings → AI proposes a due date, checklist steps, labels and links. Ordo picks the candidates itself (upcoming events and bills, recent emails and other cards that share words with the card) and the model only chooses among them by short id; replies are checked against a strict schema and each suggestion is added or dismissed by you. Local by default; a cloud provider needs the existing consent. See [docs/ai.md](docs/ai.md#boards).
- Headless: `boards list`, `boards cards`, and `boards add-card` and `boards move-card` with `--allow-changes --confirm`, naming boards, columns, labels and cards as you see them. MCP tools `ordo_boards`, `ordo_board_cards`, and with `--allow-changes`, `ordo_board_add_card` and `ordo_board_move_card` (each needs `confirm: true`). Board changes take the shared write lock.
- `boards-core` package with unit tests for ordering, the store, fields, notes, filters, links and suggestions.
- **Use AI for Boards** in Settings → AI, off by default, says exactly what Suggest sends. Suggest only offers bills with AI for Money on and emails with sorting senders on, never sends an email address, and asks before the first question to a cloud provider.
- Create, edit and delete events on your iCloud calendars. **New event** (or Cmd-N) opens a sheet with title, location, calendar, all-day, start and end, time zone, repeat (every day, week, month or year, ending on a date or after a number of times), an alert and notes. Double-click a day in Month view, or a time slot or the all-day row in Week view, to start one there; double-click an event to edit it. The event popover has **Edit** and **Delete**.
- Repeating events ask **This event only** or **All events**. One occurrence becomes an exception (RECURRENCE-ID) or is left out (EXDATE); all events move by as much as the occurrence you changed, keeping the series' exceptions and end date in step. Deleting always asks first, with Cancel as the default and a red Delete button.
- Events from Outlook and Exchange, whose time zones have their own names (like `W. Europe Standard Time`), stay at the right time when changed. An event in a time zone Ordo can't work out says so and isn't changed.
- In Week view, drag an event to move it or its bottom edge to change how long it is, in 15-minute steps. From the keyboard, Option-arrow keys move a focused event by 15 minutes or a day, and Option-Shift-Up or Down changes its length; the new time is read out and saved when you stop.
- Changes show straight away and are undone on screen if iCloud refuses them. Ordo sends each change only if the event is still as it last saw it (ETag), so a change made on your phone in the meantime is never overwritten: Ordo says so and shows the latest version.
- Times are kept in the event's time zone, so 09:00 in London stays 09:00 after the clocks change. Ordo writes standard iCalendar with the time zone included, and keeps what it doesn't edit, such as attendees, links and other apps' settings.
- Calendars added by link or file, read-only iCloud calendars and invitations from other people can't be changed, and the event popover says why.
- Headless: `calendar list`, and `calendar add`, `calendar edit` and `calendar delete` (with `--allow-changes` and `--confirm`). In the shared tool registry, `ordo_calendar_list` and the `ordo_calendar_add`, `ordo_calendar_edit` and `ordo_calendar_delete` change tools serve MCP (with `confirm: true`) and the assistant, whose confirmation card shows what will be created, changed or deleted, and in which calendar, from Ordo's own data. `calendar events` now shows each event's `uid` and `occurrence`. New error codes `conflict`, `not_found` and `read_only`. See [docs/headless.md](docs/headless.md#calendar-events).
- Assistant: press ⌘K or ⌘J (Ctrl on Windows and Linux), or **Assistant** in the toolbar, to ask about your mail, calendar and money. It looks things up with Ordo's own tools, shows each step and what it did, can open a page for you (Finances on a given month, say), and can be stopped or tried again. It sits beside the page when there's room. Suggested prompts follow the page you're on. It uses the model from Settings → AI. The conversation stays in memory for the session; New conversation, a reload or quitting forgets it. See [docs/assistant.md](docs/assistant.md).
- With Claude Code or Codex, the assistant asks for its own OK first, separately from AI sorting, and says exactly what it sends (transactions with amounts and dates, balances, bills, calendar events, sender details and your iCloud address). Nothing is sent until you allow it, and Stop sharing takes it back.
- Changes the assistant suggests (clean-ups, undo, statement imports, sorting with AI) never run until you press Confirm on a card that shows exactly what will change, built from Ordo's own dry run, and checked again at Confirm. The card says "You asked for this" only when your own words asked for exactly that and nothing untrusted had been read; otherwise it says to check it first. Cards take focus themselves and ignore presses for a moment, so they can't be confirmed by accident.
- The assistant's tool loop is strict: one JSON reply at a time, checked against each tool's schema, with a retry and a step cap. Tool results go back as escaped, delimited data marked untrusted unless they hold only numbers, and the Claude and Codex CLIs still run with their own tools off.
- One tool registry for the MCP server and the assistant (`headless/tools.ts`): adding a tool is one entry. See [docs/assistant.md](docs/assistant.md#adding-a-tool).
- Mail client. Mail → Inbox now shows your iCloud folders (Inbox, Drafts, Sent, Archive, Junk, Bin and your own), a message list with unread dots, flags and an All/Unread switch, and a reading pane. Ordo checks for new mail when you open a folder, on request and every five minutes. See [docs/mail.md](docs/mail.md).
- HTML email is shown safely: sanitised with DOMPurify, in a sandboxed frame with no scripts, forms or pop-ups, under a Content-Security-Policy that lets it connect nowhere. Remote images (tracking pixels) are blocked; **Load images** fetches that message's images through Ordo, https only, public internet only, no cookies or referrer. Plain-text mail is shown as text.
- Links in email never open inside Ordo. A sheet shows where a link really goes, warns when its text names a different site or it isn't https, and opens it in your browser. Links that hide their destination behind a user name, and non-web links, are refused. `mailto:` links start a new message (never with a Bcc).
- Attachments are listed under the message and saved with the save dialog. Inline images in a message are shown.
- Mark read or unread, flag, and move to Archive, Bin, Junk or back to the Inbox, with Undo. Keyboard shortcuts: arrows or J/K, C, R, A, F, E, Delete, U, S, Z and /.
- Search as you type across every downloaded folder (subjects, people and the text of messages you've opened), plus **Search all of … on iCloud** for older mail.
- Write, reply, reply all and forward (with the original's attachments), attach files, and save drafts to Drafts. Mail is sent through iCloud SMTP (`smtp.mail.me.com:587`, STARTTLS) with the app-specific password you already saved, only when you click Send; a copy with the Bcc list is kept in Sent and replies are threaded and marked as answered. Addresses are checked as you type and again in the main process, at most 50 recipients per message.
- Headless: read-only `mail mailboxes`, `mail sync`, `mail list`, `mail search` (cache or `--server`) and `mail read` (plain text, never marks a message read), and the matching tools `ordo_mailboxes`, `ordo_mail_sync`, `ordo_messages`, `ordo_search_mail` and `ordo_read_message` in the shared registry, so the MCP server and the assistant can both read mail (results marked untrusted). The assistant's cloud OK now says it sends the text of emails it opens. At the time there was no way to send, draft, flag or move mail from headless mode, MCP or the assistant.
- Settings → Account shows the connected iCloud account, with Connect and Disconnect (Disconnect moved here from the Inbox page).
- Mail is safer and easier to use: links whose text names a different site get a **This link may be a scam** sheet that defaults to Don't open; recipients are tokens that always show the real address, and the reading pane shows addresses beside names; saved attachments are marked as downloaded (quarantine on macOS, Mark of the Web on Windows); **Save all…** for attachments; Mail's own shortcuts (⌘R, ⇧⌘R, ⇧⌘F, ⌃⌘A, ⇧⌘U, ⇧⌘L, ⌘Z, ⌘Return to send) and a ? sheet listing them, with single keys only in the message list or a message; sheets keep focus inside and give it back when they close; the folder list becomes an icon rail in a narrow window and Compose fits a 920×600 window; emails without colours of their own follow dark mode; the message frame never shows its own scroll bar.
- Mail reads bodies more robustly: bounces show their notice (the returned email is an `.eml` attachment), Apple Mail's split HTML is joined, quoted format=flowed text keeps its quoting, and inline images Ordo won't show are listed as attachments. One email can pull in at most 2 MB of HTML and 2 MB of text, 50 inline images and 100 attachments, fetched in a few requests rather than one per part.
- `ORDO_SMTP_HOST` and `ORDO_SMTP_PORT` point an unpackaged build's SMTP at a local server for tests, like `ORDO_IMAP_*`. End-to-end tests for the mail client run against GreenMail IMAP and SMTP.

- `pnpm dev` on macOS shows the app as Ordo in the menu bar, Dock and Cmd-Tab instead of Electron, by renaming the development copy of Electron before it starts. Packaged builds were already named Ordo.
- Add a calendar by link: paste a calendar's iCal link (Google's **Secret address in iCal format**, Outlook's published ICS link, any `webcal://` or `.ics` link) and Ordo shows it under **Other calendars**, read-only, next to iCloud's. Useful for a Google work calendar that doesn't sync properly into iCloud. Ordo checks the link really is a calendar before saving it, keeps it encrypted with the system keychain, refreshes it with every sync, and says which link stopped working instead of dropping its events. Links must be https, and neither a link nor its redirects may reach this computer or the local network.
- Import an `.ics` file as a calendar of its own, with its recurring events expanded like any other.
- Calendars added by link or file work without an iCloud account, survive disconnecting iCloud, and can be removed from the calendar list. Headless `calendar sync` and `calendar events` include them.
- HSBC statements: the headerless `date,description,amount` export is read without asking, and HSBC's transaction codes are understood. Direct debits and standing orders no rule places count as Bills, foreign card fees as Fees, and the codes and exchange-rate details are dropped from merchant names.
- The Monzo app's search export (`ID, Created, Title, Subtitle, …`), including its `13/11/26, 19:58` dates, Monzo's own categories and the Subtitle shown after the name.
- Transfers between your own accounts: money out of one imported account and the same amount into another within three days, where one side names the other account or both are transfers, is paired and marked "to/from your … account". All accounts totals leave it out, so it isn't counted as both spending and income. A single account still shows it.
- More UK chains in the category rules (One Stop, Wetherspoon, Beryl, First Bus, TK Maxx…), and keywords also match plurals like `SAINSBURYS`.
- Sort with AI for Money: with **Use AI for Money** on in Settings → AI (off by default), Finances gets a Sort with AI button that asks your chosen model to categorise the merchants left in Other, one item per merchant with a cleaned name, a description with every number removed, in or out, and a rough amount band. Never balances, account details, dates or exact amounts. Rows a model categorised show a sparkle with its confidence; answers are cached per merchant and model, and applied without asking again. Same cloud consent and write lock as sorting senders. See [docs/ai.md](docs/ai.md#money).
- AI bill matching: the same run asks the model whether recurring bank payments the rules couldn't link (like `AMZN MKTP`) belong to an email sender (`Amazon`). A match only adds the emails to a detected bill marked **Matched by AI** in Bills; the model never confirms a bill.
- Change a transaction's category from the menu on its row on Finances. Your choice wins over the bank, the rules and AI; **Automatic** undoes it.
- Headless: `money sort --allow-changes --confirm` and the `ordo_money_sort` MCP tool (only with `--allow-changes`, needs `confirm: true`). `money transactions` shows who chose each category.

- New logo and app icon: four stacked cards, black at the front and lighter greys behind, on a white tile.
- Headless mode: `Ordo --headless <command>` runs without a window, for scripts, tests and AI agents. Commands for status, scan, senders, clean-up plan and run, history, undo, calendar sync and events, bills, transactions, balances, statement import and AI sorting. Human-readable by default, `--json` for one JSON document, meaningful exit codes. It calls the same main-process functions as the window, so People are never cleared and every network, mailto and cloud-AI check still applies. Read-only unless started with `--allow-changes`, and each change needs `--confirm`. Connecting an account stays in the app. See [docs/headless.md](docs/headless.md).
- MCP server: `Ordo --headless --mcp` serves Ordo's read tools to Claude Code, Claude Desktop and other MCP clients over stdio (no network port). Change tools only appear with `--allow-changes` and each needs `confirm: true`. Tool descriptions mark text from emails, statements and calendars as untrusted.
- `pnpm ordo -- <command>` runs the built app headless from a checkout.
- The app and headless runs can be open together: the databases wait briefly for each other, and scans, syncs, clean-ups, undo, imports and AI sorting take a shared write lock (`ordo-write.lock`). The window says "Ordo is busy in another window or agent" instead of clashing; a lock left by a crashed process is taken over.
- Sort with AI in Unclutter: asks the model chosen in Settings → AI about the senders in Other, with progress, Stop and a summary. Sorted rows show a sparkle with the model's confidence, and earlier answers are kept without asking again. Without a model set up, the button opens Settings.
- Bill due dates, yearly renewals and trial ends from Money appear on the Calendar, drawn so they never look like events.
- Unclutter clean-up. "Review and clear" opens a review sheet listing the selected senders, with Unsubscribe (one-click, link or email) and Move to Trash for each, a summary and a Clear button. People you've written to are refused again in the main process, whatever the window sends.
- One-click unsubscribe (RFC 8058) is a cookie-less HTTPS POST from the main process with a 10 second timeout and at most three https-only redirects. It never reaches private, local or link-local addresses, checked when connecting, so DNS tricks can't get round it.
- Unsubscribe links open in your browser; plain http links only after the sheet has shown you the URL and you've turned them on.
- Unsubscribe emails (mailto:) go out through iCloud SMTP with your app-specific password: one recipient, a short checked subject and body, at most 50 per clean-up. An address on a different domain from the sender is shown and has to be ticked first.
- Move to Trash moves every cached inbox email from those senders to your Trash in batches. Nothing is deleted.
- Clean-up history (Mail → History) lists past clean-ups with per-sender results. Undo move puts the emails back from Trash using the UIDs the server reported, and says how many couldn't be restored. Unsubscribes can't be undone.
- Settings → AI: choose LM Studio or Ollama on this computer, or your own Claude or ChatGPT login through the Claude Code or Codex CLI. Each shows whether it's running or installed, with a model picker (gpt-oss-20b preselected when you have it), a Test button that shows the reply and how long it took, and a switch to sort senders Ordo isn't sure about. CLIs are found through your login shell's PATH, so they work when Ordo is opened from Finder, and run with their tools off in an empty folder.
- Model-based sender sorting in `mail-core`: only senders the rules left in Other are sent, as names, addresses, list flags and up to five subject lines, never bodies. People are never sent or changed. Answers are cached per sender and model in the mail database.
- Settings page, opened from the gear at the bottom of the sidebar. Appearance lets you choose System, Light or Dark; the choice is saved and applied to the whole window, including the native sidebar material and the Windows title bar buttons.
- Frosted glass on the toolbar, the Unclutter table header and footer, and the connect sheet. Content scrolls under the toolbar. Surfaces turn solid when Reduce transparency is on, or where blur isn't supported.
- Solid sidebar on Windows 10, which has no Mica.
- Calendar: your iCloud calendars in Month, Week and Agenda views, using the same account and app-specific password as Mail (CalDAV). Recurring events, all-day and multi-day events and time zones are handled; calendars can be shown or hidden, and events open a detail popover.
- Calendar keeps a local cache (one month back, twelve ahead) in its own SQLite database and only refetches calendars that changed. Before you connect, it previews sample data.
- `calendar-core` package with unit tests, and CalDAV integration tests against a local Radicale server, in CI.
- Money module, replacing the Finance placeholder, with **Finances** and **Bills & Subscriptions** pages. Everything is stored in its own local database (`money.sqlite`); nothing is uploaded.
- Import bank statements as CSV from a button or by dropping the file on the window. Monzo, Starling, Revolut, Nationwide and Lloyds-style exports are recognised automatically; other layouts get a column picker. Re-importing a statement skips transactions you already have.
- Finances shows money in and out, spending by category, monthly totals and every transaction, filtered by account and month.
- Bills & Subscriptions finds recurring payments (weekly, monthly or yearly) in your statements and, when Mail is connected, links them to receipts, renewals, trial-ending and price-change emails. Confirm or dismiss what it finds, or add bills yourself. Price rises and trials ending are flagged.
- Split bills with flatmates equally, by amount or by percentage. Balances are worked out in whole pence and simplified to the fewest payments, and you can record settling up.
- `money-core` package: statement parsing, merchant clean-up, recurring detection, email hints, bill linking, split maths, a calendar feed for bills and a seam for a future local-model advisor.
- Connect an iCloud account with an app-specific password. It's checked before saving and stored encrypted with the system keychain (Electron `safeStorage`).
- Scan your inbox: headers only, cached in a local SQLite database so later scans only fetch new mail. You can stop a scan and resume it.
- Unclutter shows your real senders, sorted by rules into Promotions, Newsletters, Notifications, Receipts, People and Other. Anyone you've written to counts as a person and can't be selected for clean-up.
- IMAP integration tests and an end-to-end connect-and-scan test against a local GreenMail server, in CI.
- App shell with a native-feeling window: frosted sidebar on macOS, Mica on Windows 11.
- Home screen with links to Mail, Unclutter and Finance.
- Unclutter preview using sample data: inbox makeup, category filters and a sender list where people can never be selected.
- `mail-core` package: sender grouping and `List-Unsubscribe` parsing (RFC 2369 and RFC 8058).
- Unit tests (Vitest), end-to-end tests (Playwright), CI on macOS, Windows and Linux, and a tag-driven release workflow.

### Changed

- The inbox scan also records flags, recipients and Message-IDs, and a refresh forgets mail that was moved or deleted elsewhere, so Unclutter's counts stay accurate.
- Statement imports from a path (headless, MCP and the assistant) refuse UNC and device paths such as `\\server\share` before touching the file system, so a path can't reach the network. `ordo_import_statement` needs a full local path.
- LM Studio and Ollama errors read "LM Studio couldn’t answer (error 500). Check it’s running with a model loaded, then try again."
- Text from emails and statements shown in the terminal or on cards also loses zero-width characters, direction marks, line separators and the byte order mark.
